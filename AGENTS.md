# Правила роботи Codex

- Основне джерело істини — актуальний код поточної гілки. Перед змінами перевіряй гілку та `git status`; зберігай сторонні зміни.
- Перед завданням читай **лише релевантні розділи документації та пов'язані ділянки коду**. Не перечитуй увесь проєкт без потреби.
- [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) — карта моделей, сервісів, маршрутів, шаблонів і потоків даних. Обирай файли за таблицею «Навігація за завданням».
- [docs/CURRENT_STATE.md](docs/CURRENT_STATE.md) — реалізовані можливості, незавершені частини, відомі проблеми та перевірки. `IDEAS.md` містить плани, а не підтвердження реалізації.
- Після суттєвих змін моделей, зв'язків, сервісів, маршрутів або шаблонів оновлюй відповідні розділи `docs/ARCHITECTURE.md`; після зміни функціональності чи усунення проблем — `docs/CURRENT_STATE.md`.
- Документацію пиши українською, стисло, з посиланнями на файли та назви сутностей. Не дублюй великі фрагменти коду; розрізняй факти з коду, результати запуску й припущення.
- Працюй у межах запиту. У завданнях лише на документацію змінюй тільки документацію; не редагуй Python, HTML, JavaScript, ORM-моделі чи схему БД.
- Запускай команди з кореня репозиторію: шляхи SQLite й Jinja2 залежать від робочого каталогу. Точка входу вебзастосунку — `app.main:app`.
- Не запускай `reset.py`, `reset_test_db.py` або кореневі `test*.py` без перевірки побічних ефектів. Вони можуть видаляти БД, записувати дані або використовувати локальні Windows-шляхи.
- Для наявного набору тестів явно вказуй `python -m pytest tests/`. Фікстура `db` перестворює таблиці **тестової** БД; бережи робочі дані. Для змін обирай релевантні тести, а неперевірену поведінку не називай перевіреною.
- Не додавай реальні персональні дані, вміст робочих БД або секрети до документації та журналів.
- Не виконуй `git push` без явного дозволу користувача.
