## Метод зв’язування

КАТОТТГ дає явні повні коди рівнів. UUID побудовано окремо від них. Відсутні рівні та повторення коду вищого рівня не перетворювалися на вигадані об’єкти. Є 8 діагностичних рядків у hierarchy_issues.csv; кілька діагностик можуть стосуватися одного населеного пункту. Порожні district_id/community_id допустимі.

У НАІС відсутні ідентифікатори об’єктів і коди КАТОТТГ. Для прив’язки використано тільки точні назви області, типу й населеного пункту з однозначним результатом; якщо в джерелі є район — він також має точно відповідати поточному адміністративному району. Обробка для пошуку: крайові/повторні пробіли, casefold, еквівалентні апострофи, відомі префікси м./с./смт./с-ще та закінчення «р-н». Історичний тип смт. зіставлявся з категорією X «селище»; джерельне написання збережено.

Не застосовувались fuzzy match, транслітерація, здогадування перейменувань чи прив’язка лише за схожою назвою. Якщо район у НАІС старий або суперечливий, такий запис не приймався через збіг назви села. Це зменшує покриття, але залишає розбіжності видимими. source_city_district збережено як сирий текст: у цьому полі трапляються і назви вулиць, тому не створено автоматичних FK до внутрішньоміського району. Невідомий тип вулиці зберігається як NULL, повна назва — без змін.

## Склад пакета та імпорт

- geography_admin.xlsx: countries, regions, districts, communities, city_districts, aliases.
- settlements_01.xlsx … settlements_03.xlsx: усі населені пункти, розбиті без втрати записів. У кожній частині одна таблиця settlements; ID і FK однакові з CSV.
- CSV для всіх логічних таблиць; streets_01.csv … streets_04.csv — повний прийнятий масив вулиць частинами по 100000, остання менша.
- streets_unresolved.csv — усі непов’язані вулиці з джерельним контекстом і причиною; **не імпортувати у streets**.
- hierarchy_issues.csv та countries_excluded.csv — діагностика, не довідники.
- sources.json, validation.json, DATA_SCHEMA.md, TECHNICAL_SPEC_UK.md та оригінальні файли sources/.

**Обрати один шлях імпорту для кожної таблиці: Excel або CSV. Не імпортувати обидва як різні дані.** Для вулиць — CSV. Excel має два рядки заголовків, CSV — один. Усі коди збережено текстом. CSV UTF-8 BOM, роздільник `;`; стандартне подвійне цитування. Порожнє поле — NULL. Порожні aliases не містять вигаданих прикладів. Ключі та процедуру оновлення описано в специфікації.

## Перевірки та межі

Перевірено унікальність кодів КАТОТТГ у вихідному наборі, внутрішніх ключів і кодів ISO, існування всіх непорожніх FK та узгодженість region/district/community для населених пунктів. Справжні однойменні об’єкти з різними кодами залишено окремими. Дедуплікація НАІС усуває тільки ідентичні п’ятипольові рядки; вона не доводить тотожність фізичних об’єктів, для яких джерело не надало ID.

GUI- та SQLAlchemy-рішення тут є технічною специфікацією. Інтеграційне тестування з /admin, даними осіб і чинною БД project_2 не проводилося. Даних про будинки, поштові індекси, координати, закордонні регіони/міста та юридичні дати всіх перейменувань у цьому пакеті немає. Ручне введення залишається обов’язковою можливістю.
