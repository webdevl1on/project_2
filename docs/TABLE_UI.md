# Спільний інтерфейс і оформлення таблиць

## Scoped-дані Security 1.4

Штатка/історія/журнал отримують лише дозволені позиції, людей і категорії. `PositionTableRepository` маскує недоступні значення перед SQL-фільтрацією/сортуванням; `access_views` та каталожний `denied_fields` формують безпечні HTML/JSON/facets. Копіювання та експорт беруть уже дозволені відображувані значення; прихована колонка пресету не відкриває заборонених даних. Наявні налаштування, виділення/копіювання, Undo/Redo та нумерація повторно використовуються. Перевірка ACL діє на API і запис, навіть коли клієнт змінить DOM. Політика — [ACCESS_CONTROL.md](ACCESS_CONTROL.md).


## Компоненти та межі

`components/app_navigation.html` підключений до чинних повних сторінок: люди, анкета/форми, штатна таблиця, історія/імпорт, admin/довідники. Посилання на /persons, /events, /person-positions, /staff/history та /admin, активний розділ визначається поточним request.url.path. Dashboard не додавався, бо такого маршруту немає. Спільні стилі — `static/css/app_layout.css`; на вузькому екрані сама навігація має горизонтальну прокрутку. Політики авторизації admin й документів не змінено.

Штатка має компактні групи: згортані фільтри, Колонки/пресети/Undo, виділення/Excel/Word/копіювання/очищення, згортане форматування та «Додаткові дії». На екранах до 600 px основні фільтри початково згорнуті, їхні значення й приховані URL-параметри залишаються у формі. Імпорт і signed confirmation modal розташовані поза згортаним details, щоб modal залишався видимим при закритій панелі.

Моделі, SQLite, кадрові сервіси, SQL-запити й точність дат не змінювалися. /persons отримує додатково лише конфігурацію колонок; наявні запити та контракти sort_by/direction збережені. Зміна кольору/висоти/шрифту не означає зміни призначення, зайнятості чи Міражу.

## Дві таблиці, один менеджер

`PERSONS_COLUMNS` у `app/table_columns.py` повторно використовує назви/метадані каталогу для семи наявних полів списку: ID, прізвище, ім’я, РНОКПП, дата народження, звання, номер наказу. ID — власне інформаційне поле списку, його можна приховати/переставити. Це не нерухома системна нумерація штатки. Каталог 55 інформаційних полів штатки не змінено.

persons.html використовує ті ж ColumnController, CheckboxTree, PresetPanel, ColumnInteractions, QueryFilterAdapter, TableTimeline і TableSelection. Старий локальний column-toggle скрипт видалено. Немає другої реалізації менеджера. Ключі localStorage ізольовані за table ID persons / person-positions. Список не отримав вигаданих серверних фільтрів; при відсутності filter config спільний адаптер зберігає URL як раніше.

Порядок скриптів для повного набору: Bootstrap → table_state → column_tree → column_presets → column_interactions → table_filters → table_history → table_selection → **table_appearance** → column_visibility. **table_workspace** підключається після сторінкових кадрових обробників, якщо вони є. Спільний макрос column_visibility містить також нові елементи керування, але не містить предметної SQL/кадрової логіки.

## Висота всіх рядків, шрифти та масштаб

Новий `TableAppearance` у `static/js/table_appearance.js` використовує чинний LocalTableStorage. Параметри застосовуються до **всіх рядків даних таблиці одночасно**, у тому числі після фільтрації, сортування та перезавантаження. Заголовок має власну природну висоту. Налаштування:

- компактна 28 px, стандартна 40 px, розширена 64 px або власна висота 24–180 px;
- базовий шрифт 10–28 px, типово 14 px;
- окремий шрифт кожної колонки 10–32 px або успадкування базового;
- масштаб 75/90/100/110/125%, типово 100%.

Розміри задаються в логічних пікселях до масштабу. Масштаб множить реальні CSS-розміри рядків/шрифтів/colgroup, а не transform чи масштаб всієї сторінки. ColumnInteractions ділить фізичний pointer-delta на поточний масштаб перед збереженням логічної ширини. Через це DOM-координати клітинок, drag-and-drop і скролбар залишаються узгодженими; зміна масштабу не переписує збережені ширини. Редактор призначення тимчасово збільшує свій рядок до потрібної висоти.

Текст data-column-value лишається повним у DOM, обрізається тільки CSS (nowrap/max-height/ellipsis) і доступний у title та копіюванні. Розмір шрифту й мала висота можуть приховати більше тексту візуально, але не знищують його. Доступні всі поточні інформаційні значення, а не їхній обрізаний варіант.

Сховище `project2:table-appearance:<table-id>` містить version=1, rowHeight, fontSize, scale, fonts та fills. AppearanceModel перевіряє версію/межі/відомі ключі та дозволені кольори; пошкоджений/відсутній стан дає стандартні значення. Старий `project2:table-columns` version=1/2 і формат пресетів не змінено. Помилка збереження показується через чинний storage-error компонента.

Оформлення, як і ширини, не є окремим кроком чинного Undo/Redo: історія лишається історією колонок/фільтрів. Пресет як раніше зберігає видимість/порядок, не шрифти, заливки, масштаб чи ширини. Персонального API налаштувань не додано.

## Заливки

П’ять стриманих кольорів і очищення працюють на поточному виділенні. Ключ кожної позначки — JSON-пара **[стабільний ключ запису, data-column-key]**. Штатка рендерить `position:<position_id>`, люди — `person:<person_id>` у tr.data-row-key. Це ID записів, а не номер рядка чи назва/текст клітинки. Перестановка рядків/колонок, приховування та reload не переносять позначку на інший запис. Історичні посади різних версій мають власні Position ID.

Тимчасове виділення має окремі CSS-змінні й рамку та перекриває заливку; після очищення виділення локальна заливка знову видима. Колір не входить у SQL-фільтр, зміст клітинки, TSV/Word export або кадровий статус. Дані локальні для браузера/таблиці, не спільні між користувачами чи пристроями. Після ручного пересоздання БД зі повторно використаними ID локальні позначки не слід трактувати як історичні дані тієї БД.

## Виділення та посилання

Чинний TableSelection розширено трьома режимами: клітинки, цілі рядки та цілі колонки. Клік/drag задає діапазон; Shift розширює від опорної клітинки, Ctrl/Meta додає діапазон або перемикає вже вибраний рядок/колонку/клітинку простим кліком. Ctrl-drag з уже вибраної клітинки лишається додаванням діапазону. Через меню заголовків також можна вибирати кілька колонок із Ctrl/Shift. «Очистити виділення» та Escape очищають обидві опорні точки.

Посилання, поля й кнопки не перехоплюються. Компактна кнопка з іконкою користувача біля номера рядка зайнятої посади відкриває /person_full_info/{assignment.person_id}, має tooltip «Відкрити анкету» й не змінює виділення та редактор призначення. ПІБ і порядковий номер — звичайний текст; кнопка поза data-column-value не входить до копіювання. Вакансія не має кнопки. Кандидати Міражів мають власні окремі profile links і явний підпис «Міраж» без зміни офіційної зайнятості. ID у списку людей також веде в повну анкету.

Копіювання — виключно кнопкою «Копіювати» у вибраному Excel/Word форматі. Ctrl+C та Ctrl+A не перехоплюються. Експорт використовує поточний DOM-порядок видимих інформаційних клітинок; номер рядка лишається копійованим, assignment-редактори не входять до grid. Посилання перетворюються на їхній інформаційний текст; кнопки, форми й технічні іконки вилучаються. Значення розірваних діапазонів, TSV quoting/HTML escaping та fallback лишилися чинними.

## Прокрутка та меню

`.table-viewport` займає до 78dvh і обмежується реально доступною висотою до низу вікна. table_workspace.js вимірює верх контейнера при resize/details toggle. Обидві осі прокручуються всередині; горизонтальний скролбар розташований на нижній межі видимої області таблиці, а не в кінці всіх записів. Sticky th не прокручуються вертикально разом з даними, але зберігають горизонтальне вирівнювання.

Довгі меню обмежені висотою/мають власний scroll. У браузерах із Popover API меню всередині viewport відкриваються у **native top layer**, зберігаючи DOM-предків/існуючі listeners/Bootstrap state. Це усуває обрізання overflow без перенесення меню та переписування обробників date/filter/picker. Позиція обмежується вікном; fixed-position fallback лишено для браузерів без API. Реальне наступне прокручування viewport закриває меню, але запізнілий scroll-event від автоматичного підведення toggle не закриває його одразу після відкриття. Перевірено Chromium; окремого прогону Firefox/Safari не було.

## Форми призначення

Штатна клітинка спочатку показує тільки компактний підсумок/кандидатів. Явна кнопка або клік по вільному місцю assignment-клітинки відкриває її редактор. Одночасно відкритий лише один; клік іншої інформаційної клітинки не відкриває його. Форми й DOM-вузли не перебудовуються та не клонуються.

«Згорнути» та перехід до іншого редактора **зберігають чернетку в DOM**; змінений рядок має позначку «Чернетка». «Скасувати зміни» потребує підтвердження й відновлює початкові значення, включно з hidden person_id/підписом picker, прибирає підготовлений token та помилки. Hidden values відновлюються зі snapshot явно, бо browser .value для hidden змінює також defaultValue. Старі помилки зберігаються при простому згортанні/повторному відкритті. Чернетки не зберігаються після навігації чи reload сторінки.

person_picker.js додатково синхронізує підпис/пошук при form.reset. Signed preview, backend revision/conflicts, підтвердження перепризначення, звільнення й Міраж-сервіси не змінювалися. Оновлення/запис виконує чинна форма, а не table_workspace.

## Майбутні персональні Міражі

Зараз PersonPositionMirage лишається чинним спільним попереднім закріпленням; модель, авторизація й запити не змінені. Наступна погоджувана архітектура: персональні плани з власником із загальносистемного User, власним scope доступу та явними правами перегляду планів інших користувачів. План не повинен ставати офіційним призначенням без чинної перевірки/підтвердження. Такий принцип у майбутньому може застосовуватися до планування подій без зміни точності PersonEvent. Owner ID, приватні фільтри, нові таблиці чи міграції планів у цьому UI-завданні не реалізовано.

## Перевірки

Нові Node-тести AppearanceModel перевіряють fallback, межі, стабільні ключі та allowlist кольорів. Python-тести — незалежну конфігурацію людей і HTTP-рендер спільних controls/nav. `tests/browser/workspace.cjs` перевіряє дев’ять сценаріїв нової поведінки, включно з 123 справжніми синтетичними посадами in-memory, mobile 390px, sticky/scroll/top-layer filters, всіма рядками/шрифтами/scale-aware resize, кількома рядками/колонками, кольорами після сортування, незалежними налаштуваннями людей, чернетками/reset і помилками призначень.

Старі браузерні кадрові сценарії тепер явно відкривають редактор через спільний table_helpers, а імпорт — через «Додаткові дії». Їхні backend-перевірки не вилучені. Повний набір — 603 Python passed, 37 Node passed, 119 Chromium PASS; після фінального уточнення опорних точок повторно пройшли всі 9 workspace-сценаріїв. Два наявні deprecation warnings залишилися. Робочу SQLite не змінювали, commit/push не виконували.

Вибір версії/дати, фільтри, сортування, призначення, Міражі, пресети, виділення, копіювання й налаштування таблиці залишаються на `/person-positions`. `staff_controls.html` зберігає підтвердження перепризначення та перехід до історії. ## Два представлення подій

На /events окрема календарна матриця день/тиждень/місяць і права панель; у штатці лише одна колонка події на as_of. Це різні read views спільного PersonEvent, без копії поточного стану. Обидва екрани використовують event_views.css, event_display.py та SVG-легенду. «Компактний вигляд» штатки застосовує набір із восьми колонок через чинний ColumnController, зберігаючи можливість повернення в історії та власні пресети. Новий інфоключ event_on_date підтримує header hide/select, resize, порядок і копіювання; фільтр типу події є в журналі. Більша таблиця зберігає внутрішню прокрутку/sticky header, коротка не розтягується порожньою областю. Докладно — [EVENT_VIEWS.md](EVENT_VIEWS.md).

## Налаштування календарного журналу

`journal_controls.js` зберігає ширину ПІБ і видимість № рядка/№ посади/короткої посади у власному ключі localStorage. Місячна навігація зберігає GET-фільтри, сортування й масштаб. Журнал і штатка лишаються без пагінації, з попередніми механізмами прокрутки. Поведінка штатних пресетів, копіювання та Undo не змінена. [EVENT_CONTROL.md](EVENT_CONTROL.md).

## Порядок колонок журналу

Журнал також використовує ColumnModel/ColumnInteractions через локальний адаптер. dragHandleSelector дозволяє drag із кнопки сортування тільки для конфігурації журналу; попередні таблиці мають стару поведінку. № закріплена в порядку, ширина ПІБ/видимість/sticky/скрол збережені. Сортування серверне, CSV відповідає видимому порядку. [EVENT_CORRECTIONS.md](EVENT_CORRECTIONS.md).

## Компактний журнал і спільні інструменти

/events розділяє календар start/end та стан штатки as_of. Верхня панель групує навігацію, параметри, фільтри й дії без зміни загального стилю. Штатка та журнал спільно використовують value_filter.html/column_filter_menu.js і table_copy.html; Bootstrap display utilities більше не показують приховані пошуком варіанти. QueryFilterAdapter працює з URL, TableSelection — з тим самим keyed DOM. Журнал opt-in підтримує нативний «Текст», «Клітинки/Рядки/Колонки», Word/Excel і вузький Ctrl+C для клітинок; решта таблиць зберігає старі клавіатурні правила. Wrap Text зберігається в чинних локальних налаштуваннях журналу. Top-layer popovers table_workspace доступні через data-table-viewport без зміни геометрії штатки. ## Історія штатних призначень

`/staff/history` — список згорнутих карток **посад** вибраної версії. GET version_id/q зберігають вибір і пошук номера/назв; вакансії та посади без історії теж показуються. Усередині окремі поточні, архівні (новіші першими), майбутні й згорнуті анульовані призначення. Один Bootstrap-редактор/Person Picker обслуговує всі картки, без розмноження списку людей. Анулювання/відновлення — окреме підтвердження, історія змін — Modal із таблицею різниці полів/авторів/UTC. ProfileDates дає ДД.ММ.РРРР; приховані API-значення залишаються ISO. Чинний перехоплювач форм зберігає всі поля після помилок, фокусує видиме поле дати, не закриває Modal і не виконує навігацію при відмові. Підписане підтвердження переведення зберігає чернетку та дозволяє повернутися до редактора.

Колонки, фільтри, копіювання, пресети та Undo/Redo штатки/журналу не змінені. Анульоване призначення не є фактичною зайнятістю й не включає людину до журналу на дату стану.

## Організаційне дерево та сукупний штат

`/admin/organization` показує датоване дерево довільної глибини; Drag & Drop/стрілки змінюють лише порядок сусідів. Зміна основного батька, оперативного зв’язку й зіставлення посади — окремі явні дії. `/admin/organization/staff` використовує чинні навігацію, Bootstrap, ProfileDates, MFA/CSRF, службові повідомлення; помилка не очищує чернетку форми. Новий незалежний менеджер таблиць не доданий.

У штатці типовий вибір за наявності OrgCoverage — «Сукупний чинний штат за джерелами підрозділів» на as_of; явна версія й чинні URL-параметри доступні. Кожен історичний Position зберігає власний ID, а одна чинна посада потрапляє в один рядок. Каталог, ширини, виділення, копіювання, фільтри, пресети й Undo/Redo не змінюють форматів зберігання. Дані організаційного керування не додані як технічні колонки щоденної таблиці. Правила джерел та сумісності — [ORGANIZATION.md](ORGANIZATION.md).
