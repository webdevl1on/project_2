# Географія, місце народження та адреси

## Зберігання

`GeoUnit` → `geo_units`: власний ID, kind (country/region/district/community/settlement/street), name, normalized_name, parent_id, необов'язкові iso_code (ISO 3166 для країни) та katottg_code. Назви й коди не є глобально унікальними. `GeoAlias` → `geo_aliases`: unit_id, оригінальна альтернативна назва, normalized_name та historical. Без засівання довідник порожній; автоматичного створення назв немає.

`PersonBirthplace` → `person_birthplaces`: один запис на Person, текстові country/region/district/community/settlement та необов'язкові *_id, settlement_type. Вулиці, будинку й інших детальних складових немає. Дата народження залишається в Person без змін.

`PersonAddress` → `person_addresses`: person_id, kind registration/actual/correspondence, ті самі географічні компоненти, street/street_id, street_type, house, corps, building, apartment, room, postal_code, note. Усі компоненти необов'язкові й текстові; будинки/квартири/індекси з нулями, літерами й дробами не перетворюються на числа.

Оригінальні текстові знімки та необов'язкові довідникові ID співіснують. Перейменування GeoUnit не змінює записаних адрес. Видалення довідникового об'єкта обнуляє ID за FK, але залишає текст (з'єднання має виконувати PRAGMA foreign_keys=ON). Збереження не вимагає КАТОТТГ, ISO або збігу з довідником. Історичне написання можна ввести вручну або вибрати за достовірним alias; нечітких автоматичних прив'язок немає.

## Історія та транзакції

Сервіс `geography.save` володіє однією service_transaction(immediate=True); Repository не комітить. Заміна адреси архівує попередній запис і додає новий атомарно. Частковий унікальний індекс за person_id/kind дозволяє тільки одну is_active адресу кожного типу. record_id + revision відхиляють застарілі чернетки, зокрема після створення іншої адреси з початковим revision. Помилка вставлення відкочує архівування.

Необов'язкові date_start/date_end — точні фактичні дати, якщо відомі; система не підставляє день зміни як дату початку/завершення. is_active означає актуальний обраний запис, а не обчислення стану на довільну дату; перевірки перетинів предметних періодів адрес зараз немає. UTC created_at/updated_at та revision беруться з чинного SystemTimestamps. Це окрема історія, без змін PersonEvent/призначень.

## Пошук, м'яка перевірка, UI

`Router → services/geography.py → repositories/geography_repository.py → SQLAlchemy`.

`GET /geography/search?kind=settlement&q=...&parent_id=...` — серверний префіксний пошук за назвою/alias, мінімум 2 символи, максимум 20 результатів. parent_id обмежує піддерево, тож можна шукати населений пункт за областю без зазначення району/громади; без батьківського ID пошук глобальний. Однойменні результати мають власні ID та підпис предків. Весь довідник у браузер не передається. Довідникові записи не створюються цими маршрутами.

Спільна форма в повній анкеті, вкладка «Загальна інформація»: birthplace, registration, actual. correspondence підтримано моделлю/сервісом для майбутнього інтерфейсу. geography.js використовує debounce 250 мс та лічильник покоління відповідей. Зміна батьківського компонента прибирає залежні ID/підказки, але зберігає введений текст; копіювання реєстрації переносить поля в незалежну чернетку actual без ідентифікатора запису/revision. За непорожньої чернетки потрібне підтвердження заміни.

Сервер перевіряє тип/наявність посилань, ієрархію та відповідність тексту name/alias. Стани: matched (усі заповнені географічні назви підтверджені ID), mismatch (виявлена суперечність), unknown (недостатньо підтвердження). Попередження містять довідниковий варіант; не блокують збереження й не виправляють текст. Ручний точний збіг не створює ID автоматично. Для невідомої назви/порожнього довідника збереження працює. Статус — знімок останньої серверної перевірки, не автоматичне переписування всіх адрес після оновлення довідника.

`POST /persons/{id}/geography/{block}` повертає HTML-компонент. JS замінює тільки відповідний блок та історію, зберігає інші чернетки й відкриті секції. Помилка валідації показує причину, залишає поля й відкриту форму, переводить фокус на повідомлення. Мережева/неочікувана серверна помилка залишає початкову DOM-форму. Поточна політика доступу до кадрових сторінок незмінна.

Український індекс (явна Україна або country.iso_code=UA) — необов'язковий рядок із 5 ASCII-цифр. Іноземні індекси довільні текстові. Посилання Укрпошти відкриває https://index.ukrposhta.ua/ з target=_blank і rel=noopener noreferrer; API/парсингу/автопідстановки немає. `format_address` пропускає порожні компоненти й не додає зайвих ком.

## Безпечне оновлення SQLite

Зупинити сервер та інші процеси запису. З кореня репозиторію:

```sh
python -m app.database.migrate_geography --database data/database/project2.db
```

Потрібна актуальна попередня схема зі статтю/відмінками та штатними тригерами; старіші БД спочатку проходять відповідні попередні міграції. Команда перевіряє SQLite header, integrity/FK, таблиці/колонки/тригери, створює узгоджений backup `*.before-geography-*.sqlite3` через SQLite backup API (0600), під BEGIN IMMEDIATE додає тільки чотири географічні таблиці/індекси. Старі таблиці не перебудовує, записи не змінює. При помилці повний rollback DDL; повторний запуск — no-op. Автоматичного запуску міграції/видалення БД немає. Попередню migrate_name_cases обмежено її первісними таблицями, щоб нові моделі не робили стару міграцію непрацездатною.

## Контракт майбутнього імпорту (ще не реалізований)

Заплановано захищений `/admin` з preview/підтвердженням, не публічний запис. Excel: аркуші `units` та `aliases`, заголовки рядок 1, дані з рядка 2. CSV: два окремі UTF-8 файли з такими самими заголовками. Усі коди — текст, без втрати нулів.

- units: `external_id, kind, name, parent_external_id, iso_code, katottg_code`.
- aliases: `unit_external_id, name, historical` (historical: true/false).

external_id — стабільний зовнішній ключ у межах достовірного джерела, не назва й не внутрішній SQLite ID. Для готового пакета вже створено geo_import_links (див. нижче); для довільного джерела майбутній GUI повинен явно визначати namespace/політику ключів. Батьки можуть бути в інших рядках; імпорт має перевіряти існування, дозволений порядок рівнів, цикли, дублікати ключів і коди ISO/КАТОТТГ. Можна пропускати відсутні проміжні рівні. Вулицям не вигадувати КАТОТТГ. Однакові назви різних об'єктів дозволені; alias створюється тільки за явними даними. Оновлення довідника не змінює текстових знімків людей. Видалення/перейменування — лише явна контрольована операція; часткове завантаження не означає видалення відсутніх одиниць. Цей формат задокументований для підготовки джерела, GUI імпорту географії поки немає.

## Перевірки

`python -m pytest tests/test_geography.py -q` — 10 тестів на тимчасових SQLite: ручні/повні/часткові дані, іноземні індекси, пошук/aliases/ліміт/однойменність, м’які конфлікти, знімки після перейменування, історія/revision/rollback, HTTP-чернетки, backup/idempotency/DDL rollback. `COLUMN_STAGE=geography PYTHON=.venv/bin/python CHROMIUM_PATH=/usr/bin/chromium node tests/browser/column_visibility.cjs` — п’ять сценаріїв, включно з незалежним копіюванням, збереженням після reload та відкиданням застарілих відповідей автодоповнення.

## Програмне засівання готового пакета

seed_geography адаптує CSV reference_data/geography до GeoUnit: країни → регіони → райони → громади → населені пункти → вулиці, найближчий відомий батько без вигаданих рівнів. geo_sources зберігає джерельні метадані; geo_import_links має унікальну пару kind/external_id, unit_id, source_id/version, digest пакета та деталі (source_row, підтипи, ISO3/numeric, контекст вулиці). На повторі UUID зберігає ID, при зміні UUID той самий однозначний офіційний код у межах kind повторно використовує GeoUnit. Для вулиць без офіційного коду використовується UUID. Відсутні об’єкти не видаляються; текстові адресні знімки не змінюються.

108 внутрішньоміських районів записуються в окрему geo_city_districts з FK на населений пункт; не стають адміністративними district і не входять до адресного поля district. КАТОТТГ-ролі Києва/Севастополя окремі за kind, як у джерелі. Імпорт потоковий, batch=500, одна транзакція компонента, без сотень тисяч ORM-об’єктів. Поточний aliases.csv порожній; адаптер aliases географічних GeoUnit підтримано, alias city_district потребуватиме окремого розширення й зараз явно відхиляється. GUI географічного імпорту ще не реалізований. Деталі reset, checksum LF/CRLF та виключені набори — [DATABASE_RESET.md](DATABASE_RESET.md).

## Форматування й комбіновані поля типів

Публічний `services.geography.format_address(record, extended=False)` повторно експортує чистий форматтер `utils/address_format.py`; він приймає ORM-об’єкт або dict і не виконує запитів/записів. SETTLEMENT_TYPES/STREET_TYPES в app/geography.py — централізовані повні типи й скорочення. Вони спільні з editable datalist-компонентом components/geography_type.html. Вибір не обов’язковий: власний текст і порожнє значення дозволені, maxlength залишається чинним. «Інше» означає вільне введення, а не службове значення, яке підставляється в БД.

Для явної України (`Україна`/`Ukraine`/UA/UKR) області з відомого переліку чи з явним словом «область» виводяться з `обл.`, райони — з `р-н`. Без країни український контекст визначається тільки за відомою областю/особливим регіоном; для невідомих регіонів країна не вгадується. АР Крим, Київ, Севастополь і невідомі особливі/історичні регіони не отримують автоматичного `обл.`. Однакова спеціальна міська одиниця в region/settlement не дублюється. Явна іноземна країна завжди вимикає автоматичні українські адміністративні суфікси.

У короткому форматі громада прихована, якщо заповнений населений пункт; `extended=True` додає її. Якщо населеного пункту немає, громада залишається. Стандартні типи скорочуються (`м.`, `с.`, `с-ще`, `смт`, `х.`, `вул.`, `просп.` тощо), невідомий тип зберігає написання. Уже наявні префікси/суфікси не дублюються; номери з нулями, літерами й дробами залишаються текстом. Один форматтер використовується місцем народження, поточними й історичними адресами та може використовуватися майбутнім експортом.

Автопошук населених пунктів/вулиць повертає необов’язковий `type`, тільки якщо тип у збережених GeoImportLink.details однозначний; коди city/village/settlement/special_city явно перекладаються у повні українські значення. Відсутні/суперечливі метадані не дають підказки типу. Порожнє поле можна заповнити після вибору об’єкта; непорожній тип замінюється лише з підтвердженням. Тип не визначається за схожістю назви. *_id, правила м’якої перевірки та історії незмінні.

Приклад короткого рядка: `Україна, Дніпропетровська обл., Криворізький р-н, м. Кривий Ріг, вул. Бруно, буд. 01А/2, кв. 003`. Повні значення SQLite не змінюються. Схема БД, root Excel та імпортери в цьому етапі не змінені; reset/повторне засівання не потрібні.
