# Освіта, сім’я та особисті розпорядження

## Дані

`app/models/profile_records.py` додає три незалежні таблиці. Кожен запис має справжній FK `person_id → persons.person_id`, власні ID, revision, автоматичні точні UTC `created_at`/`updated_at` із чинного SystemTimestamps. Кількість записів не обмежена. Усі задані предметні дати — SQLAlchemy Date, точні; порожні залишаються NULL.

| Модель / таблиця | Предметні поля та перевірки |
| --- | --- |
| PersonEducation / person_education | Обов’язковий level_code; необов’язкові started_on, ended_on, institution, faculty, specialty (тексти до 500 символів). Якщо обидві дати відомі, ended_on ≥ started_on. Відсутність дати завершення не означає завершеного навчання. |
| PersonFamilyMember / person_family_members | Обов’язкові kinship і full_name (до 500); необов’язкові birth_on, death_on, phone (рядок до 100), address_text (оригінальний текст до 2000, включно з переносами), географічні текстові компоненти та optional FK на GeoUnit. death_on ≥ birth_on, якщо відомі обидві. |
| PersonDirective / person_directives | Тільки number String(300) і issued_on Date, обидва nullable; хоча б одне значення обов’язкове. |

`app/profile_records.py` централізує коди/підписи й метадані форми. Освіта: general_secondary, vocational, professional_prehigher, higher_short, higher_bachelor, higher_master, higher_specialist. Сім’я: wife, husband, mother, father, son, daughter, brother, sister, grandfather, grandmother, other. Значення вибираються явно, без визначення за ПІБ.

Дипломи, оцінки, наукові ступені, додаткові поля розпоряджень не додані. Родич не створює Person або контакт. Освіта та розпорядження не створюють завдань, штатних призначень або історії служби.

## Шари, зміни та історія

`routers/profile_records.py → services/profile_records.py → repositories/profile_record_repository.py → models/profile_records.py`.

Сервіс використовує чинну `document_transaction` / `service_transaction(immediate=True)`: BEGIN IMMEDIATE, повторна перевірка ролі/належності/revision, одна транзакція для предметних даних і PersonnelAudit. Repository не комітить. За помилки — повний rollback. Передавання ID запису іншої людини або застарілої/відсутньої revision під час редагування відхиляється.

Редагування виправляє вибраний запис, не додає копії. Попередні/нові значення зберігаються у чинному append-only PersonnelAudit з entity=education/family/directives, реальним actor_id та точним UTC часом. Окрема таблиця аудиту, ролі чи ACL не створювалися. Поточний вільний режим і явно ввімкнений захист працюють як раніше.

## API

Базовий шлях: `/persons/{person_id}/profile-records/{kind}`, де kind — education, family або directives.

- GET — метадані полів, записи, журнал, роль; Cache-Control: no-store.
- POST — створення, JSON `fields` із предметними значеннями.
- POST `/{id}` — редагування; додатково обов’язкова `revision`.

Дати в API залишаються ISO `YYYY-MM-DD` або null; системні часові позначки не приймаються з форми. Невідомі поля відхиляються. Чинний current_user і CSRF застосовуються за поточною конфігурацією авторизації; actor_id з клієнта не приймається.

## Адреси сім’ї

Оригінальний `address_text` незалежний від структурованих country/region/district/community/settlement/street та їхніх ID. Використано GeographicFields, GeoUnit/GeoAlias, `/geography/search` і `services/geography.prepare`; нового адресного довідника немає.

Підказки доступні глобально без обов’язкових предків. Населений пункт можна вибрати першим; пропущені компоненти не блокують збереження. Зміна тексту прибирає лише ID цього поля, решта прив’язок зберігається. Кнопка підказки задає явний ID; текстовий або неоднозначний збіг самостійно не створює посилання. Сервер перевіряє тип ID, aliases, відповідність тексту та ієрархію. matched/mismatch/unknown — знімок перевірки; суперечність показує попередження, а не виправляє документальний текст. Невідомі та довільні адреси дозволені. Оновлення довідника не переписує збережені значення.

## Інтерфейс анкети

`person/components/additional_records.html` і `profile_records.js` — один редактор для трьох розділів, керований серверними метаданими. `+ Новий запис` відкриває чисту форму; «Редагувати» завантажує конкретні ID/revision. При помилці чернетка та режим зберігаються. Успіх оновлює лише список, очищує/згортає редактор і показує спільний ProfileUI Toast. Картки початково згорнуті; точні дати вводяться/показуються спільним ProfileDates у ДД.ММ.РРРР.

Hash `#education`, `#family`, `#directives` відкриває вкладку; `#education-17`, `#family-17`, `#directives-17` відкриває конкретну картку після асинхронного завантаження, без автоматичного переходу в режим редагування. Число — ID запису, не людини.

## Явна міграція SQLite

Сервер самостійно не мігрує БД. Зупиніть сервер та інші підключення. З кореня репозиторію:

```sh
python -m app.database.migrate_profile_records --database data/database/project2.db
```

Потрібна актуальна попередня схема включно з останньою міграцією ВЛК. Перевіряються SQLite integrity/FK, попередні таблиці/колонки, індекси й guards. Maintenance lease захищає від одночасного обслуговування. SQLite backup API створює окремий `*.before-profile-records-UTC-RANDOM.sqlite3` до запису. Одна транзакція додає тільки три нові таблиці та їхні індекси; старі реквізити/тригери не переписуються. Помилка DDL має rollback зі збереженням backup. Часткова/несумісна схема відхиляється; повтор успішної міграції — no-op без нового backup.

Для нової порожньої БД чинний реєстр моделей/init_db створює всі таблиці. Попередні міграції пропускають ці майбутні таблиці у своїх перевірках; це дозволяє проходити попередні кроки у належному порядку. Робочу БД під час реалізації не мігрували й не пересоздавали.

## Перевірки та межі

`tests/test_profile_records.py` — мінімальні/повні записи, точність дат, коди, рядковий телефон, оригінальна адреса, aliases/відсутні предки/розбіжності/unknown, власник, revision, транзакційний rollback, реальний автор та чинний доступ. `tests/test_profile_records_migration.py` — backup, повтор, незмінність старих даних/DDL, часткова схема, відмова DDL і створення нової БД. `tests/browser/additional_records.cjs` — форми, дати в en-US, підказки реального тестового довідника, помилки, очищення, редагування без дублікатів, reload/hash.

Видалення записів, окремий граф родинних зв’язків, файли освіти й розпоряджень, нові колонки штатки та додаткові ACL не входять до цього етапу. Історія змін доступна в журналі, окремого відновлення попередньої редакції немає.
