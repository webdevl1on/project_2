## Контекст

`project_2` (FastAPI + PostgreSQL, Windows-сервер). Резервування Security 1.5–1.6 працює на реальному сервері: щогодинні повні копії з drill, щоденний аварійний Excel о 18:00 Europe/Kyiv у захищену папку, копіювання на BitLocker-USB. Кнопки панелі лише ставлять завдання в чергу; worker (Task Scheduler, щохвилини `run-once`) виконує їх за 1–2 хв. Користувачі не розуміють, чи щось відбувається: після натискання немає видимого прогресу, результат з'являється лише після ручного оновлення, час показується як сирий UTC ISO.

Прочитай лише: `docs/BACKUP_AND_RESTORE.md` (розділи «Аварійний архів», «Права, MFA й аудит»), `docs/UI_DESIGN_SYSTEM.md`, `app/routers/backups.py`, `app/services/backups/commands.py` (`status`, `enqueue`), `app/services/backups/worker.py` (стани завдань, 5-хв строк авторизації ручних завдань), `app/services/backups/emergency.py` (`latest`, маніфест), `app/services/backups/usb.py` (результат `export`), `app/templates/admin/backups.html`, `app/static/js/backups.js`, `app/static/js/access_reauth.js`, `app/static/js/security_session.js`, тести `tests/test_backup_http.py`, `tests/test_security16.py`.

## Вимоги

### 1. Менеджер завдань (прогрес)
- Після натискання будь-якої дії (`create`, `verify`, `emergency`, `usb`, `statistics`) показувати **картку завдання**: назва дії українською, стан і час постановки.
- Стани: «У черзі — очікує worker (до 1 хв)», «Виконується», «Готово», «Помилка: <зрозумілий текст>», «Прострочено — worker не підхопив завдання за 5 хв (перевірте, що завдання Project2-Backup увімкнене)».
- Поки є активні (`QUEUED`/`RUNNING`) завдання — опитувати `/admin/backups/data` кожні 3 с; без активних — як зараз, 30 с. Опитування не продовжує сесію (як зараз).
- Під час активного завдання того ж типу відповідна кнопка `disabled` з підписом «Виконується…»; після завершення — повідомлення «Готово» або помилка і автоматичне оновлення блоків.
- Блок «Останні завдання»: 5 останніх з тими самими людськими станами (замість сирого рядка), коди помилок — через словник людських пояснень (`EMERGENCY_GENERATION_FAILED`, `USB_COPY_FAILED`, `STORAGE_NTFS_ACL_REQUIRED`, `USB_BITLOCKER_REQUIRED`, `USB_VOLUME_CHANGED_OR_NOT_ALLOWED`, `USB_INSUFFICIENT_SPACE`, `BACKUP_AUTHORIZATION_EXPIRED`, `BACKUP_DRILL_FAILED`, `BACKUP_DRILL_APPROVAL_REQUIRED`, `EMERGENCY_QUOTA_EXCEEDED`, `MFA_REAUTH_REQUIRED`; невідомий код — показати код як є).
- Якщо сервер відповів 403 `MFA_REAUTH_REQUIRED` — помітне повідомлення поруч із кнопкою (не лише дрібний текст угорі) + чинний modal повторного підтвердження; після підтвердження дію **не повторювати автоматично** (як зараз), а попросити натиснути ще раз.

### 2. Коротка інструкція на сторінці
Згортуваний блок «Як користуватися» (за замовчуванням розгорнутий, стан згортання — у `localStorage` з try/catch):
1. Резервні копії бази створюються автоматично щогодини й перевіряються тестовим відновленням — нічого натискати не потрібно.
2. Excel (читабельна копія даних) формується автоматично щодня о 18:00. «Створити нову версію Excel» — сформувати позачергово зараз.
3. Щоб записати на флешку найсвіжіші дані: (а) «Створити нову версію Excel» → дочекатися «Готово»; (б) вставити флешку P2-EMERGENCY; (в) «Створити аварійний архів на USB» → обрати носій → «Підтвердити» → дочекатися «Готово»; (г) безпечно вийняти флешку.
4. На флешку копіюється **остання готова** версія; кнопка USB нову версію не формує.

### 3. Дані про версії (час — Europe/Kyiv, формат `ДД.ММ.РРРР ГГ:ХХ`)
- «Остання повна копія бази»: час знімка, розмір, «тестове відновлення успішне» так/ні.
- «Остання версія Excel на сервері»: час формування, розмір книг, кількість файлів документів.
- «Остання копія на USB»: час, мітка носія, яка версія Excel скопійована (її час формування), кількість файлів. Дані брати з наявних подій/записів worker (`usb` SUCCESS details) — за потреби розшир `commands.status` безпечними полями.
- Позначка, якщо остання USB-копія старіша за останню версію Excel: «На флешці не найсвіжіша версія».
- Усі нові поля статусу — **без** шляхів ОС, GUID томів, SID, ключів, хешів (як зараз; Security 1.6).

### 4. Дрібне
- Списку USB-носіїв додати `id`/`name` (попередження DevTools «form field should have id or name»).
- Таблиця копій: час у Kyiv замість ISO.

## Межі
- Не змінювати логіку резервування, worker, криптографію, права/MFA/ACL, формат копій і маніфестів. Лише HTTP-статус (безпечні додаткові поля), шаблон, JS, CSS.
- Не додавати HTTP-завантаження файлів чи шляхів.
- Повторне використання наявних компонентів дизайн-системи, без нових залежностей.
